# Inventario Dux: depósitos y antigüedad

Contrato autorizado el 2026-09-08. Este documento describe el código; las ejecuciones y publicaciones remotas se acreditan por separado. Los registros anteriores de `docs/validation/` se conservan como historia.

Dux sigue siendo la única autoridad de productos, nombres, SKU, categorías, precios y existencias. El retiro irreversible operativo de `0018` continúa vigente: ninguna fotografía editorial crea productos manuales. Compras, pagos, pedidos nuevos y reservas permanecen cerrados.

Cada lectura completa consulta `/v2/empresas`, `/v2/sucursales?id_empresa=...` y `/v2/depositos` antes de `/v2/items`. El directorio debe estar completo y sin IDs duplicados. Se aceptan solamente depósitos habilitados de la empresa configurada; las altas y bajas se descubren nuevamente en cada ejecución. `DUX_DEPOSIT_ID` permanece como referencia de compatibilidad del contexto, sin filtrar el universo de stock. El recurso de ítems no admite un filtro por empresa: el aislamiento se establece con el token autorizado y la propiedad verificada de cada depósito, sin agregar parámetros ficticios.

La proyección comercial v2 conserva opcionalmente `warehouseStocks` por producto, con depósito, variante y las tres cantidades tal como las informa Dux. Una cantidad ausente es `null`, nunca cero. Los depósitos sin filas informadas se muestran sin cantidades. Se preservan decimales y negativos. El inventario cuantitativo D1 conserva sólo filas totalmente cuantificadas; el snapshot público conserva también los campos parciales o ausentes y el desglose administrativo/público. Las filas de otra empresa o de depósitos deshabilitados no se incorporan.

No se suman filas de diferentes depósitos o variantes: `/v2/items` no acredita unidades comparables. Una sola fila cuantificada puede mostrarse como observación individual. Las restantes se muestran desglosadas; no se deducen unidades por el nombre del producto. Un cambio de nombre conserva la URL previamente publicada para el mismo código Dux.

La fecha de inventario es el inicio de la lectura completa que lo respalda, conservadora respecto de la página más antigua. La finalización de la sincronización es una fecha distinta. Una lectura fallida, un GET público o un cambio editorial no rejuvenece las cantidades. La ficha actualiza el aviso de antigüedad al superar 900 segundos incluso si queda abierta en el navegador. La reconciliación registra incumplimientos observados en `admin_audit`, acción `dux.stock_freshness_exceeded`.

El primer intento del 2026-09-08 trasladó la programación a `config/dux-cron.jsonc`: un relay de Cloudflare cada cinco minutos, con secreto independiente `DUX_CRON_SECRET` y sin ruta HTTP pública. La configuración se verificó por API y se volvió a publicar mediante Wrangler, pero la observación no registró eventos ni lecturas Dux de ese actor, superando los plazos de propagación documentados. Los recibos e intervalos de observación se conservan fuera de Git; no se atribuye una causa interna del proveedor que no pudo demostrarse.

La programación vigente vuelve a `.github/workflows/dux-reconcile.yml`, minutos 2, 7, 12 y sucesivos cada cinco minutos. El margen contempla una lectura completa que en la línea base rondaba 86 segundos. GitHub ya demostró ejecuciones automáticas, aunque con demoras de horas; la nueva frecuencia tampoco acredita cumplimiento sin observación. El relay Cloudflare conserva código y secretos para diagnóstico, con lista de crons vacía. Antes de abrir el gate GitHub se debe confirmar por API que Cloudflare quedó sin cron; nunca coexistirán ambos relojes. Se mantienen lock D1, concurrencia del workflow, timeout, presupuestos, reintentos acotados y último snapshot válido. La comprobación de todas las fichas se ejecuta en los despachos manuales, sin prolongar cada ejecución automática.

El rollback compatible cierra el gate del scheduler y conserva `0018` y los datos actuales. Puede usarse el runner autenticado manualmente durante la investigación. Nunca se restaura una versión que reconstruya catálogo o stock manual. No se promete cumplimiento por configurar el cron: se requieren cuatro corridas automáticas consecutivas, intervalos y observación de la antigüedad entre publicaciones. Un despacho manual no cuenta en esa muestra.

Se mantienen límites explícitos de tamaño, paginación y escrituras D1; un proveedor que exceda el presupuesto detiene la publicación y exige revisar el límite con evidencia. No se amplía facturación ni se rebaja el objetivo de 15 minutos.
